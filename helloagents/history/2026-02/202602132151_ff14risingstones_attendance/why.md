# 变更提案: FF14 石之家每日签到（多账号 + 推送）

## 需求背景
石之家提供每日签到，可获得社区经验与商城积分。手动签到容易遗忘，且多账号管理成本较高，因此需要一个可在 GitHub Actions 等环境自动执行并推送结果的工具。

## 产品分析

### 目标用户与场景
- **用户群体:** 同时拥有多个盛趣账号、希望稳定获取每日签到收益的玩家
- **使用场景:** 每日固定时间自动签到；失败时及时获知并手动更新 Cookie
- **核心痛点:** 忘记签到、难以追踪多账号执行结果、Cookie 失效排查成本高

### 价值主张与成功指标
- **价值主张:** 零密码、低风险、可观测的自动签到与结果推送
- **成功指标:** 每日执行成功率≥99%（在 Cookie 有效前提下）；失败可在 1 次通知内定位原因

### 人文关怀
不采集账号密码，不尝试规避验证码/风控；避免在日志/通知中输出任何可用于复用的敏感凭据。

## 变更内容
1. 新增“石之家每日签到”定时任务，支持多账号 Cookie
2. 新增执行摘要与通知推送（可选）
3. 可选：自动领取当月档位奖励（默认关闭，避免误操作争议）

## 影响范围
- **模块:** tasks / utils / ci
- **文件:** 预计新增 Nitro 任务、HTTP 客户端、GitHub Actions 工作流与文档
- **API:** 新增内部任务触发入口（Nitro tasks）；对外仅为仓库使用说明
- **数据:** 可选 KV 记录每日状态（防重复/重试补偿）

## 核心场景

### 需求: 多账号每日签到
**模块:** tasks
对多个账号的 Cookie 执行每日签到，并输出汇总结果。

#### 场景: GitHub Actions 定时执行
每日定时触发工作流执行签到。
- 预期结果: 每个账号返回成功/已签/未登录/失败状态
- 预期结果: 将执行摘要通过通知渠道推送

#### 场景: Cookie 失效
Cookie 过期或被注销导致请求返回未登录。
- 预期结果: 通知中明确提示“请先登录/更新 Cookie”

### 需求: 结果推送通知
**模块:** utils
将多账号执行结果聚合为一条（或少量）通知。

#### 场景: 成功/部分失败
- 预期结果: 通知标题固定、内容包含账号统计与失败原因概览

## 风险评估
- **风险:** Cookie 过期/失效导致无法签到
  - **缓解:** 将错误码 `10403` 明确标记为“需要更新 Cookie”；支持多账号逐个定位
- **风险:** 平台风控/接口变更导致失败
  - **缓解:** 保持请求与官方前端一致（method、content-type、tempsuid 形态）；提供可调重试与可观测日志
